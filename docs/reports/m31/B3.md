# B3 — checkpoint sweeper fixture

The checkpoint fixture now prepares every ref for a session in one real Git
transaction before publishing any of them. The sweeper still runs every 50 ms,
with the same zero-age policy and all original deletion, live-session, unknown
session, Fork pinning and Workspace removal assertions. Production code is
unchanged.

Post-Archive seeding waits for the existing fake attachment-store Archive
callback. The reactor invokes that callback after checkpoint pruning finishes;
this replaces the previous 100 ms sleep and excludes late Archive pruning as the
reason the seeded refs disappear.

## Controlled evidence

A repository-local `reference-transaction` hook observes the real Git prepared
phase, recording pending updates and refs already visible to a concurrent
sweeper. It changes no refs or pruning result. The regression asserts one
preparation with four pending updates and zero visible refs, then checks every
published ref. The hook and observations live inside the owned disposable repo
and are removed with it; no global Git configuration is changed.

The old helper failed this regression:

```
1 0
1 1
1 2
1 3
```

The replacement passed with `4 0`. The old sequence therefore exposes partial
checkpoint sessions to real pruning while later subprocesses are still creating
refs. Batch preparation creates all lock paths before any checkpoint is
published. Git readers need not observe multi-ref commit atomically, but there is
no later lock-directory creation following an already published first ref.

This experimentally establishes the unsafe publication window, not the exact
internal Git directory-creation/deletion interleaving. E0's retained broader run
failed creating the `s-sw-gone/<Turn>/after` namespace at the old helper line 105;
E0's unchanged isolated replay passed 3 tests / 8 assertions in 1.48 s. Neither
that replay nor this work proves the historical error's precise cause, a
permission defect, an Editor defect, or a FIFO failure.
