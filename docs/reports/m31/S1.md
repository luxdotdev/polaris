# S1 · Independent lazy syntax highlighting

The exact delivery head is supplied by the native Claim; this report is part of that commit.

## Delivered behavior

Syntax remains entirely local to the Desktop App. Detection and loading accept
no Host, trust, installation, connection or language-server dependency. No
buffer/save/tab runtime or Settings wiring changed.

- `.env`, `.env.local`, `.env.example`, other `.env.*` variants and `*.env` use
  original dotenv assignment syntax. `.envrc` remains shell. Multiline quoted
  values, escaped quotes, comments and interpolation receive syntax tokens.
- Prisma has an original local stream mode for schema blocks, attributes,
  native types, strings, numbers, function calls and comments.
- Java and PHP use CodeMirror language packages; Lua uses the existing legacy
  modes dependency. Go module/workspace directives have original local modes.
- Common associations now include C/C++/C#, Ruby, XML/SVG/plist, Dockerfile and
  Containerfile variants, INI/properties/EditorConfig and diff/patch. Existing
  TS/TSX/JS/JSX, JSON, CSS, HTML, Markdown, Python, Rust, Go, YAML, TOML, SQL and
  shell support stays available. Extensionless scripts use shebang detection;
  matching handles case and both path separators. Unknown files remain plain.
- Markdown uses CodeMirror's GFM base, including strikethrough. Fences resolve
  exact aliases using the first info word, ignoring trailing fence metadata.
  Unknown fences remain plain. Cheap `LanguageDescription`s request only the
  encountered grammars; the Markdown package's existing HTML/CSS/JS dependencies
  remain transitive, rather than loading the whole catalog.
- All grammar imports are dynamic. Concurrent requests share a promise; failed
  loads produce plain text, evict the cache and permit a subsequent request to
  retry. Failed fence descriptions also reset their pending load through
  CodeMirror's existing rejection handling. A failed fence stays plain until
  another parse/request retries it.

Moonlit tokens are unchanged (`DESIGN.md`, rule/syntax-is-moonlit). Stream modes
supply standard highlight tags; Prisma calls use the existing function tag.
The three new local modes are original Polaris code, with no borrowed upstream
implementation or additional attribution requirement. They are lexical syntax
modes, not validators, full structural parsers or language servers. Existing
MDX/JSONC/JSON5 associations retain their Markdown/JSON parser limitations.

## Contracts for later lanes

`model/language.ts` exports `LanguageId`, `LanguageMetadata`, `LANGUAGES`,
`LANGUAGE_IDS`, `LANGUAGE_NAMES`, `LanguageAssociation`, `languageByName` and
`languageFor`. Metadata carries display name, document language ID, extensions,
exact filenames and aliases. This is the seam for manual selection and Settings;
association precedence/persistence and selector wiring belong to later lanes.

`tsx` maps to `typescriptreact`, `jsx` to `javascriptreact`, `shell` to
`shellscript`, `plain` to `plaintext`; other IDs use their syntax ID. `gomod`
and `gowork` match `go.mod` and `go.work`. Actions uses `yaml` syntax/document ID
and a `github-actions` fence alias; contextual provider selection belongs to
Host tooling. K1 and F1 received these contracts through native peer messages.
No provider/catalog identifier is coupled to local syntax.

`cm/languages.ts` exports `loadLanguage`, `fencedLanguages`, `fenceLanguageId`
and an injected `createGrammarLoader` seam for failure/deduplication checks.

## Performance and limits

Both baseline and changed Editor benchmark commands ran under `m31-bench`, using
temporary profiles and fake files. Baseline code was built before source changes;
new dependencies were installed but unused by that baseline build.

| --- | ---: | ---: |
| 1 MiB renderer open, median of 5 | 10.7 ms | 27.4 ms |
| Large-file key-to-paint p95 | 8.1 ms | 9.7 ms |
| Small-file key-to-paint p95 | 7.8 ms | 8.4 ms |
| Vim insert key-to-paint p95 | 8.5 ms | 8.5 ms |
| Empty app footprint | 271.1 MiB | 340.6 MiB |
| 20-tab app footprint | 500.1 MiB | 532.7 MiB |
| 20-tab incremental footprint | 229.0 MiB | 192.1 MiB |

Commands: `exec-5ecddc84-d53c-4b6f-881f-b6e7917e6ade` (before) and
`exec-2b5788f0-b124-4e2b-b68f-a708df40ce15` (after), both exit 0.
JSON/logs: `/tmp/m31-s1-before.{json,log}`, `/tmp/m31-s1-after.{json,log}`.
Reproduce with `bun apps/daemon/src/main.ts lease m31-bench -- node
apps/desktop/scripts/editorBench.ts --build --json <output>`.

These are shared-Host, single paired runs, not quiet-machine certification.
Open latency and absolute memory increased; no controlled background-load sample
was captured to attribute the difference. No baseline was rewritten. The script's
150 ms open/1024 MiB memory/two-frame typing checks passed, but its approximately
6 ms measured frame and two-frame threshold do **not** certify the literal
one-frame/display-rate budget. B1 owns complete-build budget acceptance and
committed machine-baseline comparison. The build manifest verifies lazy startup
structure; it does not turn noisy timings into a no-regression claim.

Syntax adds no Daemon polling, watchers or timers. No Daemon engine/protocol/store
behavior changed, so spec/PBT/trace and Daemon scenario reruns were not required
for this lane. Production servers/accounts/SSH configuration, real Sightline and
user configuration were not modified; there were no direct writes to `~/.polaris`. Daemon access was limited to the assigned lease
and read-only retrieval of this worker's command receipts.

Initial failures were corrected: sandbox temp-directory restrictions required an
escalated authorized dependency install; process inspection required escalation
for the lease; undeclared `smoke` resource was replaced with `m31-bench`. Initial
spacing/complexity/type and custom-token defects were fixed before final checks.
No hooks were bypassed. No unfinished S1 implementation work remains. Follow-up
verification belongs to the already planned B1/U2 merged-build acceptance lanes.
