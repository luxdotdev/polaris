## Delivery and product brief

The developer reads a Markdown document's current unsaved source on its own
Host and checkout. The caller supplies that source and its identity; navigation
stays in shared Editor navigation, and fragments remain inside this preview.
The remembered external-image choice belongs to the user and its Workspace,
independent of language execution trust. M2 owns source/preview view identities,
active-document following/locking and buffer coordination. C1 owns main's
preferences/media bridge; G2 owns authenticated canonical Host media access and
actual registration. These fixtures do not prove those production integrations.

The entry point is `MarkdownPreview` in `markdown/index.tsx`. It lazy-loads static
Streamdown and shares existing on-demand Shiki/Mermaid loaders and moonlit theme.
GFM includes tables, tasks, strikethrough, autolinks, code fences and sanitized
HTML. Default raw/sanitize plugins remain installed; the default harden plugin would block
relative Host paths before routing, so custom components own URL hardening. Images and links use
custom components, and raw HTML picture/source selection is disabled; neither document URLs nor filesystem paths become renderer
network/file requests. Strict Mermaid additionally rejects source configuration,
image/icon resource nodes and active HTML; HTML labels are disabled. Script,
iframe and other unsafe HTML stays sanitized. Heavy renderer failure keeps the
current source readable. No idle timers, watchers, polling or language processes; queued admission alone has a finite deadline.

DESIGN.md `rule/density-through-tokens`, `rule/syntax-is-moonlit`,
`rule/remote-is-normal`, `rule/starlight-is-rare` and visible keyboard focus govern
spacing, colour and states. Both themes use existing tokens. Native tables can
scroll horizontally, images fit the content width, and fragments focus stable
heading anchors without motion. Repeated/formatted headings get deterministic
suffixes; sanitized HTML anchors are scoped to the preview root.

## Integration contract for C1, G2 and M2

`MarkdownPreviewProps` accepts `source`, `document`, `hostLabel`, optional
`LanguageApi`, and async `openDocument`/`openExternal` callbacks. `PreviewDocument`
contains `hostKey`, authoritative `hostId`, complete `LanguageCheckout` and the
absolute Markdown `path`. The callbacks retain the Host and checkout; a relative
link provides the resolved absolute target plus decoded fragment. External
navigation receives a credential-free HTTP(S) URL and must use main's external
navigation policy. Unsupported schemes, absolute file paths, malformed escapes,
backslashes, control bytes, query paths and lexical checkout escapes are inert.
Canonical filesystem authority remains on the Host, including symlink/race
checks; lexical routing is not proof of canonical containment.

On mounting, `languages.preview.policy.get` receives `{hostKey, workspaceId}`.
The response is decoded with `LanguagePreviewPolicy` and must match both the
Host and Workspace. Consent uses `languages.preview.policy.set` with an exact
policy whose `externalImages` is `allow`, keeping sanitized HTML, disabled
scripts, strict Mermaid and media limits. Failed reads/saves stay fail-closed.
M2 should remount the preview when an external Settings change revokes or changes
its media policy; the current contract has no policy subscription. An absent
adapter displays unavailable Host media while source and local rendering remain
usable. Main must recheck stored consent on every external fetch.

Relative images call `languages.preview.media` with `{hostKey, checkout,
documentPath, relativePath, maxBytes}`; `relativePath` is decoded and remains
relative to the Markdown directory, with legitimate contained `..` supported.
G2 authorizes checkout membership, resolves the canonical document/media path
with race/symlink containment, bounds raster bytes and returns its BlobId.
C1 resolves that blob using the existing connection and produces the accepted
`LanguagePreviewMediaView`. External images call `languages.preview.external`
with `{hostKey, workspaceId, url, maxBytes}` only after matching stored consent;
C1 owns pinned-public credential-free fetches and redirects/deadlines.

The renderer decodes output MIME/base64/declared byte count and accepts only
PNG/JPEG/GIF/WebP/AVIF, up to the policy limit (at most 10 MiB). C1/G2 own raster
signature/content validation, not these injected fake responses. Each preview
pool limits active plus pending requests to 16, and active bytes plus pending
full-response reservations to 32 MiB. Temporary pending pressure waits in a FIFO queue of at most 16 jobs, each with a
15-second admission deadline. Capacity beyond the queue or genuinely retained
byte/slot limits fails closed; there is no cross-document cache or retry/poll loop. Each image owns one lease;
source removal releases it. Closing/changing Host, checkout, document or policy
disposes the pool and revokes every URL once. Replies after disposal are rejected
before decoding a Blob or allocating a URL. Image effects pass an AbortSignal to `pool.acquire(source, signal)`; source change
or unmount removes/rejects queued jobs. Running cancellation rejects locally and
retains its full reservation until the main request settles, discarding its late
reply before validation/allocation. Queue deadlines are cleared on admission,
cancellation or disposal. The generic `LanguageApi.request` has no AbortSignal;
already-dispatched calls remain bounded by main's deadlines/bridge disposal,
and are discarded locally rather than falsely claimed as transport-cancelled.
