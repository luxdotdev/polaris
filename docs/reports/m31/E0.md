## Construction and lifecycle handoff

Import from `features/editor/lsp/index.ts`. This folder is detached: it has no
startup registration, global window access, automatic discovery, process launch,
document synchronization, disk write, durable draft mutation, tab ownership or
AI ghost-text ownership. It uses the accepted S1 `LANGUAGES` metadata through
`documentLanguageId`, preserving TSX/JSX and shell LSP IDs.

E1 supplies a `LanguageApi` from C1 and constructs `LanguageFeatures` with live
`buffer()` and `providers()` getters. `LanguageBuffer` contains the canonical
URI, monotonic unsaved version and actual immutable CodeMirror `Text`; supply
the buffer's `lineSeparator` for CRLF. `bufferText` serializes with that separator.
Each `LanguageProvider` contains the originating `hostKey`, acquired identity,
actual negotiated capabilities and current `LanguageSyncAck`. Supply providers
in effective configured order, at most 32. Disconnected/unready/untrusted
providers must not be included as usable contexts. The adapter validates the
ack/version/context again; an acknowledgment is queue admission, not proof of
completed server analysis.

E1 remains the only open/change/close/save synchronization owner. Update these
getters from accepted ordered sync results and context events. On buffer edit,
selection-dependent request replacement, context invalidation, connection loss,
capability change or replacement, call `invalidate()`. On final consumer detach,
call `dispose()`. A replacement generation requires new acquired/synchronized
contexts and current full unsaved snapshots; never retain the old provider's ack.
Neither disposal nor reconnect writes unsaved content to disk.

Requests have instance-unique IDs, a default 5-second deadline (hard maximum
30 seconds), at most 32 outstanding remote calls (hard maximum 128), and one
replacement/cancellation lane per feature. Each provider call receives its own
context, required sequence and exact document version. Provider-only resolve and
execute requests never broadcast. Cancellation settles locally and sends
`languages.cancel`; an unresponsive transport retains its pending reservation
until actual settlement, preventing repeated cancelled calls from accumulating
unbounded remote work. Real broker cancellation/reaping remains T1/G2 evidence.
No polling or idle timer is installed; deadlines exist only during requests.

Results require the exact request ID and echoed fence, the same immutable document
and version, current provider identity/ack and still-advertised method. Results
are aggregated in provider order regardless of completion order. Malformed or
failed providers are omitted independently. Method payloads are decoded with
Effect Schema and bounded arrays/text before use. Adapters do not print payloads,
unsaved text, Settings, environment values or server errors.

## CodeMirror and feature consumers

`completionSource(features, coordinator)` is a real public CodeMirror
`CompletionSource`; attach it through the existing language/completion extension
seam in E1. It uses `CompletionContext` abort notifications with `onDocChange`,
returns source-labelled completion options and preserves provider text edits,
list defaults and per-provider negotiated trigger characters.
Plain same-buffer primary/additional edits are validated for ranges/overlap and
dispatched as one `input.complete` transaction with `pickedCompletion` annotation.
Common numeric LSP snippet tabstops are converted for public `snippetCompletion`.
Rich snippets, snippet/additional-edit combinations, commands and ambiguous edits
go to the required `CompletionCoordinator.propose` callback, carrying the original
item/provider/buffer and replacement range. E1 must handle or visibly reject that
proposal after revalidation; silently dropping its extra effects is incorrect.
No completion transaction accepts closed-file or tree changes.

`hoverExtension` uses public `hoverTooltip`, hides on changes and uses textContent
for server text. It never injects HTML or evaluates Markdown. E1 owns styled,
sanitized popovers and keyboard/focus integration. `signature`, `navigation`
(definition/type-definition/implementation), `references`, `documentSymbols` and
`workspaceSymbols` return typed source-labelled payloads. Navigation back history,
references peek and symbol UI remain E1. Location links retain target selection
and origin ranges; workspace symbols can retain unresolved location/data.
`resolve` gates completion/action resolve and actual supported methods;
`execute` accepts only commands advertised by the originating provider.

`LanguageDiagnosticFeed` watches each context, independently replaces provider
sets, checks URI/generation/version and chains unchanged results only from the
matching previous result ID. `refresh()` unsubscribes old feeds, clears old sets
and binds the newly supplied contexts; late callbacks from old subscriptions are
ignored. `clear()` removes demand; `dispose()` makes that final. Unversioned and
last-known data remain explicitly labelled in the typed feed and are excluded
from `cmDiagnostics` current-buffer decorations. Decorations deduplicate matching
range/source/message/severity, retain provider labels and cap the aggregate at
2000. Invalid ranges are omitted. `pullDiagnostics` is an awaitable bounded
method-specific report adapter with per-provider previous result IDs; E1 chooses
negotiated push/pull demand and owns converting report freshness into Problems.

`diagnosticsExtension(features)` is a per-view `ViewPlugin`, with a public `feed`
on its instance. It batches decoration dispatch into one microtask and stops its
feed on document changes/destroy. E1 should retain that plugin value and call
`view.plugin(plugin)?.feed.refresh()` after new sync acknowledgments/context
replacement; immediate resubscription before the new buffer is synchronized is
incorrect. The view plugin does not own the shared `LanguageFeatures` lifetime.

`positionAt`/`offsetAt` negotiate UTF-8, UTF-16 or UTF-32 independently for each
provider. CodeMirror offsets use UTF-16; conversion counts UTF-8 bytes or Unicode
code points as appropriate. Invalid lines, out-of-line characters and split
surrogate/code-point boundaries are rejected. Cross-file results retain original
LSP ranges and provider encoding; E1 must use the target buffer, never the source
buffer, when converting navigation targets.

## Awaitable save and proposal boundaries

`format(provider, preflight, signal)` returns a validated `LanguageFormatOutcome`;
it waits for the selected format operation and checks the original snapshot,
context/fence/version, deadline and reply. A Provider formatter must match the
originating provider and advertise formatting. None returns Skipped. Executable
availability and authorization remain the Daemon preflight's responsibility.
Disposal/invalidation/caller abort cancel locally and send cancellation. The same
outstanding remote-call bound applies to formatting. F2 owns revalidating ranges,
applying edits, serializing saves and separate disk-version checks. Formatting
failure must still save current text with the required feedback; disk-save
failure must remain a separate failure. No file save occurs in this adapter.

`codeActions` preserves decoded edit/command/resolve data. `rename` returns the
validated feature result and proposals. `editProposals` returns only unexpired,
current-provider proposals with matching fences, capped at 128. R1 snapshots and
revalidates them at acceptance and owns persistent drafts, preview, coordinated
undo and X1/X2 resource-operation recovery. Commands and server applyEdit must use
that same acceptance boundary. Nothing here applies resource operations or
claims that server-side edits have become durable.

## Narrow shared subscription correction

`LanguageSubscriptionItems` previously selected streaming RPC `successSchema`
wrappers. In Effect 4 RPC, those schemas describe Streams, not individual feed
items. Both the listener Type and main bridge decoder were therefore wrong.
The corrected three entries use `LanguageContextEvent`, `LanguageInstallProgress`
and `Schema.Array(LanguageAvailability).check(Schema.isMaxLength(512))`.
No request/method/error/capability/activation semantics changed. The tests decode
actual typed events/progress/arrays, prove each old wrapper rejects those same
payloads, and reject malformed/oversize input including a 513-entry array.
U0 was notified; U1/C1/E1 must consume this exact corrected shared head during
Lead's serial integration.
