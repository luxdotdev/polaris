## Delivered boundary

The detached Host runtime consumes D1 `ProjectDiscovery.layer` and
`ExecutionTrustService.layer` through `LanguageBroker.layer`. The service exposes
Effect operations and a cancellable Stream; its scoped finalizer closes owned
processes. `createLanguageBroker` is the Promise factory used by bounded fixtures
and measurement scripts. There is no production connection handler or capability
advertisement in this change. G2 owns authenticated composition and connection
wiring; no Client-supplied path is sufficient authority to execute a process.

The context key includes authenticated Client, canonical checkout, effective
project, provider and configuration fingerprint. Wire generations are monotonic
within a broker. Ordered document acknowledgments mean the snapshot cut was
accepted, not that server analysis finished. Requests require an exact generation,
acknowledged sequence and document versions before dispatch and after response.
Typing, cancellation, revocation, configuration invalidation, connection loss and
restart prevent older results or edit responses from becoming usable.

Processes start on document demand. Open documents retain them across view changes;
last document and interest release starts bounded grace. Initialization negotiates
encoding/sync/features, responds to configuration requests and sends initialized,
configuration and current full snapshots in FIFO order. A generation retirement
clears all private documents and pending operations. New generations require new
Client snapshots; no stale edit notification or unknown edit result is replayed.
The pure XState lifecycle bounds automatic crash retries to two, with explicit
manual restart resetting the budget. Retry timers cannot resurrect old drafts.

Trust is rechecked at launch resolution, spawn, document/request dispatch and
server request handling. G2 must notify revocation/configuration changes through
`invalidateTrust` / `invalidateConfiguration`, disconnect Clients, and inject the
authenticated authoritative registry. Launch resolution is an injected private
boundary that must distinguish missing executable/version/prerequisite, trust,
platform and managed artifact facts. It must not install anything. T1 introduces
no ShellCheck readiness claim or guessed companion metadata. A1 artifact review
and activation remain external prerequisites.

`requestRaw` is the ordered, fenced formatter seam. `prepareEdit` is the edit
coordinator seam: snapshot and revalidate affected resources before producing a
P1 proposal. Without it, server applyEdit fails closed. Forwarded proposals and
server responses remain generation/version bound; this runtime writes no drafts
or resource edits to disk and grants no edit acceptance. E1/G2 must supply their
assigned coordinator/Client paths.

Server handling includes configuration, Workspace folders, bounded dynamic
capability registration, progress/cancellation, refresh, showMessage forwarding,
push/pull diagnostics and unsupported-request errors. Unversioned push diagnostics
are explicitly marked; closed/stale document diagnostics are discarded. Private
server log/stderr text is withheld from public events. Unknown response IDs cannot
complete another generation's request.

## Bounds and cleanup

Content-Length framing has an 8 KiB header and 1 MiB body limit, fatal UTF-8 and
schema validation, duplicate/malformed length rejection and at most 256 frames
per input chunk. The process FIFO holds at most 256 messages / 8 MiB, 64 pending
requests, a 10 s write deadline and a maximum 30 s request deadline. Context command
queues hold 256 operations; acquisition concurrency is eight, contexts 32,
interests/documents 1,024 per context, process reservations eight (including launch and retiring-process cleanup), document bytes
1 MiB each / 8 MiB per context / 32 MiB per Host broker. Server traffic, registrations,
progress tokens, forwarded requests, logs and diagnostic counts are bounded.
Each context permits 16 subscribers with 256 events / 2 MiB per subscriber;
slow streams terminate, and return/abort wakes pending reads and releases slots.

Graceful close attempts shutdown/exit before the owned process group is terminated;
a 500 ms fallback kills remaining owned descendants on POSIX. Windows has the
Bun child-process fallback and is not platform-tested here. Scoped request Effect
interruption sends cancellation. Cancellation retains the original process connection; discovery in flight is fenced
on Client disconnect. Grace expiry removes the old lookup before asynchronous
shutdown, whose cleanup waits only its own process. Detached contexts and event queues retain no
durable replay of unsaved content and introduce no idle polling.
