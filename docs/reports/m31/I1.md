## Implemented adapters

- `install/host.ts`: one bounded Daemon-owned registry, immutable Host bindings,
  deduplicated construction and the accepted per-Host/tool/version installer.
  Catalog/limits/platform/adapters are copied before use. Rebinding a Host to
  different options fails closed. Construction performs no runtime probe or
  download. Private storage remains explicitly supplied and Host-scoped.
- Demand-only observations have four concurrent operations, 64 consumers,
  64 pending public requests and a two-second preflight/approval deadline.
  Installation still has I0's bounded jobs/consumers/download/expansion/storage
  and 120-second deadline. No idle polling or timers are introduced.
- `availability/probes.ts` and `version-process.ts`: existing configured or
  explicitly supplied search paths only, bounded lookup and trusted version
  commands with explicit parsers. Missing executable and unknown/incompatible
  version remain separate facts. Untrusted demand executes no probe. No runtime,
  compiler, companion, package lifecycle script or project dependency is installed.
  The POSIX runner uses no shell or inherited credentials, caps both streams at
  4096 bytes, bounds execution/cleanup, kills its owned group and requires ESRCH
  to confirm cleanup. EPERM and cleanup uncertainty fail closed. Probe disposal
  aborts and awaits owned runner cleanup; resource-bearing observations must bind
  that disposer through Host `disposeObservations`.
- `install/download.ts`: explicit injectable Host HTTPS transport, exact URL,
  manual redirects, omitted credentials, bounded body/content length, cancellation
  and transport cleanup. Integrity remains checked before decoding and storage.
  There is no default live fetch or Client endpoint discovery. An authenticated
  relay can implement the typed fetch port but is not certified by these fixtures.
- `install/archive.ts`, `decode.ts`, `evidence.ts`: bounded gzip expansion and
  strict POSIX ustar parsing; no filesystem extraction or subprocess. Reject
  traversal, links, special entries, PAX/GNU extensions, ambiguous names/numbers,
  corrupt checksums/trailers, truncation, unsafe modes and expansion limits.
  Read-only canonical evidence reads verify pinned audit/notice/packaging hashes.
  Evidence notices merge only when original archive bytes agree. I0 rechecks all
  paths, notice retention and actual filtered output before writing.
- Binary, phar, gz and strict tar.gz/npm bytes have pure adapters. A declared
  bundle or go-module source requires a separately verified prebuilt-bundle
  adapter and is explicitly rejected here; no source build or dependency install.
  PAX/GNU and actual catalog packaging/platform gaps remain visible.
- `install/selection-ledger.ts`: bounded shared launch/selection admission,
  explicit idempotent releases and no automatic stale-reservation stealing.
  Selection excludes all active generations; generation admission excludes
  pending selection and incompatible installed identities. Disposal refuses
  outstanding reservations rather than forgetting child lifetimes.
- Core `afterSelection` finalization releases the session reservation on the
  underlying job's settlement, including cancellation/failure. Cancellation of
  one consumer cannot release its peer's reservation. Pending acquisition is
  awaited with a cleanup bound; late acquisition is released and uncertainty
  retained as recovery-required. Core rechecks exact approval after the barrier.
  Approval remains default deny and is never derived from catalog audit status.
- Read-only storage recovery facts expose uncertain `.stage-*`, `.active-*`
  and `install.lock` entries outside a known local job. Host inspect/install
  reject these as recovery-required, preserve the selected version and do not
  delete uncertain files. No automatic pruning or lock stealing is implemented.
- Explicit update and identity-selected rollback use the immutable descriptor
  of the target version and recheck approval, prerequisites and live guards.
  Feature availability verifies the actually selected receipt descriptor,
  including the old working version after failed updates; pinned candidate and
  installation/progress facts remain separate.

## Exact composition ports

Lead/H1 owns core composition, central registration, authentication, transport,
capability advertisement and RPC layers. No files in those Areas were changed.

`createHostInstallations().get(options)` returns a singleton `HostInstallation`:

- `inspect(toolId, phase: "install" | "feature", trusted)` returns availability.
- `install(toolId, intent, guard, signal?)` returns a per-request `InstallHandle`.
- `rollback(toolId, retainedIdentity, guard, signal?)` selects only verified storage.
- `current`, `versions`, `progress`, `recoveryFacts`, `stats`, `subscribe`, `dispose`.

`guard` must independently validate the authenticated principal, registered
checkout, current trust and current session. It runs before/after preflight and
again at selection. One consumer owns only its returned `cancel`; shared job ID
is observation identity, never cross-principal cancellation authority. Subscribe
returns an unsubscribe function; scope it to the authenticated request/connection.
Initial availability is an explicit inspection; progress can trigger subsequent
demand inspections. No availability polling or fabricated runtime observation.

`HostLanguageInstallation.layer(host)` in `availability/service.ts` exports the
Effect inspect/install/rollback/current/subscribe port. Interruption cancels its
consumer. The registry owner awaits disposal at Daemon scope shutdown. This
adapts directly into H1's `LanguageProviderAccess.availability`.

`managedLaunchAdapters` in `availability/launch.ts` exports matching
`reserveLaunch(request)` and `resolveLaunch(facts, lease, request)` ports.
`LaunchAdmissionRequest` and `LaunchSelectionLease` are type-only imports from
H1's supplemental `runtime/launchAdmission.ts`; they are not duplicated in I1.
Request carries exact context/facts, the runtime-owned AbortSignal and isCurrent.
Lease carries immutable selected identity, async validation, synchronous current
assertion and release. A WeakMap binds the actual held lease to its request.

Reserve validates actual selected receipt, exact approval and current authority,
then takes the same Host ledger used for installer selection. Resolve checks
that ownership, selected identity, current approval/feature prerequisites, plan
identity, canonical installed entry, observed developer runtime, discovered cwd
and Lua discovery disablement. It propagates admission.signal, checks after
awaits and makes no installation or standalone replacement controller. Missing
plan/approval/ownership denies launch. Runtime retains release ownership.

H1 and Lead confirmed the original facts-only resolver signature could not hold
selection exclusion through spawn. Operator 3750 and H1's exact 3747 contract
now define the supplemental runtime port: reserve BEFORE resolution, validate
after awaits, synchronously assert immediately before native spawn, release only
after raw child/OrderedConnection settlement; retain failed or pending teardown.
I1 supplies the matching adapter and shared ledger. H1 owns supplemental runtime
integration and Lead serially assembles both before J1 freeze. Until that exact
supplement is present, the isolated d423 checkout has an unresolved type import;
scoped typed lint failures are disclosed below. No production generation is
represented as certified by the passing fake lease tests.

## Install job ownership supplemental source

Operator 3953 requested the remaining bounded consumer/progress registry after consuming the guarded observation delta in J1. `install/ownership.ts` exports `createInstallOwnership(host)` over the same supplied HostInstallation; it constructs no Host, ledger, runtime or approval adapter. Lead owns RPC mounting and supplies independently authenticated connection objects, actual lifetimes and action grants. Execution-trust mutation grants are not install/cancel/watch permission and are not A1 artifact approval.

`bind({principal, lifetime, requireCurrent, authorize})` captures that exact principal object and lifetime and returns one stable owner port. A different object with the same ClientId has no former jobs; changed authority references, sealed lifetimes and foreign job IDs are rejected. No payload lookup grants ownership. Explicit authorize receives install/cancel/watch actions with immutable requested tool/version/intent. Missing authority denies. Current principal and captured observation guards are rechecked after grant awaits.

`start({toolId, version, intent, retainedIdentity?}, admission?, signal?)` validates pinned version/intent, or the exact retained identity and version for rollback, and retains the actual per-consumer InstallHandle. The actual independent grant/current/admission guard is passed to Host selection and original cancellation signals remain attached. `cancel(jobId, signal?)` detaches only that owner's handles, preserving other owners sharing the same underlying jobId. Completed terminal progress remains completed after a later cancel. No update, rollback, artifact approval or activation is inferred.

`watch(jobId, signal?)` returns `{updates, dispose}`. It replays the latest actual Host progress and coalesces to one newest slot per stream, with action/current/admission checks before each yield and after waits. Consumer cancellation is reported as its actual error; it does not fabricate an underlying shared job failure. One Host subscription feeds owned entries; there is no polling or idle timer. Lead must scope stream disposal to the RPC demand.

Limits are 16 active owners, 64 pending/active consumer handles, 128 globally retained job records, 32 records per owner, 64 streams globally and eight per owner. Completed unwatched records may be evicted under pressure; active or watched records are retained and new admission fails closed when capacity is full. Pending grants count toward capacity. Sealing a lifetime synchronously cancels handles and detaches streams; disposal awaits pending handle acquisition and owned handle results without asking for fresh permission. It does not dispose the shared Host or cancel another owner's handles; underlying shared job/storage cleanup remains the Host registry's responsibility at outer shutdown.
