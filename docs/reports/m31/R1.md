## Implementation

`refactors/coordinator.ts` validates decoded format-2 proposals, SHA-256 fingerprints of the entire ordered proposal, exact snapshots and deterministic complete current inventory. Server `workspace/applyEdit` always offers a preview; no server request autoaccepts. User code actions/rename may apply directly only for one text path without resource operations. Acceptance rechecks independent authority, expiry, current drafts and fences before persistence and again after storage latency.

`refactors/group.ts` and `storage.ts` retain every affected source and overwritten/deleted dirty descendant's original text, disk version/text, document version and draft revision, together with the ordered proposal and mappings. One bounded strict IndexedDB transaction commits the complete group, with revision CAS. A receipt is exposed only after transaction completion and readback. Abort, quota, unsupported strict durability or unknown commit cannot authorize Host moves. Existing asynchronous spill acknowledgments are not durability evidence. Each encoded group is capped at 32 MiB; accepted proposal and receipt schemas enforce X2 aggregate wire limits. No truncation or unresolved-group pruning occurs.

The private `verifyReceipt` port reads the actual persisted prepared group, checks independently authenticated scope, exact full proposal/fingerprint/resources and complete current dirty inventory, and revalidates fences. A Client-provided `durable:true` is insufficient. Authentication comes from `authority()`, never from the proposal. Private group lookup/status contains original texts and must not become a wire endpoint. G2 repeats checks after Host lock waits and owns authenticated server routing.

Create/rename/delete projections follow documentChanges order. Rename/overwrite preserves source and displaced originals; recursive deletion retains descendant drafts. Reconciliation uses confirmed applied/restored steps and authoritative receipt revisions. Partial forward results project only the confirmed prefix; unresolved/recovery-required outcomes freeze prior drafts. Unknown responses persist an unknown group and expose status lookup, never new acceptance replay. Undo/recovery uses persisted operation/outcome revision CAS and Host ownership. Stale or changed same-revision responses are rejected.

The runtime uses grouped drafts for reopened files with their persisted document/draft revisions and refactor ownership, holds accepted drafts out of autosave, rekeys moved open buffers/tabs, and updates CodeMirror only after durable reconciliation. Ordinary save/discard retires undo ownership while retaining originals. Open text/revision/disk changes, newly occupied buffers and newer closed drafts refuse coordinated undo. The existing F2 save coordinator remains the single save authority.

`RefactorPreview` is mounted in the actual EditorPane, including its empty-file state. It shows ordered resource operations, original/proposed drafts and displaced originals, explicit Accept/Reject, partial receipts, Check outcome and guarded Recover/Undo. Registration is Host plus checkout scoped. Restart recovery clears any prior card, filters the full independently authenticated Client/checkout/context generation and rechecks authority after storage reads before exposing a card.
