## Consumer ownership and contracts

The public interface is `packages/protocol/src/languages/index.ts`, exported
through `@polaris/protocol`. Its README specifies authentication, validation,
capability gating, queue ordering, recovery and media constraints. The exact
contract mapping and F1's ten requirements are in `P1-contract.md`.

| Consumer | Interface and responsibility |
| --- | --- |
| D1 | `base.ts`, `settings.ts`, `rpc.ts`: canonical nested project discovery, authenticated checkout identity and execution trust; Worktrees inherit Workspace trust, Review Checkouts require a separate grant |
| T1 | `documents.ts`, `broker.ts`, `capabilities.ts`: generation-scoped processes, contiguous sync sequences, actual negotiated capabilities, bidirectional server requests, cancellation, transport/depth/queue limits and ordered shutdown |
| C1 | `apps/desktop/src/shared/languages.ts`, optional `PolarisApi.languages`: decode input and output schemas; authenticated Host routing, main-owned preferences/media and reconnect snapshots |
| X1 | `edits.ts`: version-checked resource operations, prepared/applied durable receipts, partial outcomes and guarded recovery; no filesystem-wide atomicity |
| M1 | `settings.ts` preview policy and preview media RPC/IPC: sanitized GFM/strict Mermaid, Host path containment, independent Workspace consent, main-only external image fetches and bounded raster bytes |
| I1, after A1 | `catalog.ts`, K1/K2 descriptors: verified private staged installations, distinct install/feature prerequisites, progress, updates and rollback; never install developer runtimes/toolchains |
| E1/F2/R1 | Document/request fences, proposals, persistent Client drafts and unified save outcomes; exact current-buffer/disk revalidation, preview acceptance, grouped undo and unknown-outcome queries |

`LanguageRpcs` remains separate from `DaemonRpcs`; current protocol version 1
and Agent Session streams remain unchanged. Optional IPC tables are detached
from active routes. Advertise a capability only after its complete handler and
Client path are implemented and tested. Old peers retain unknown-capability
filtering and cannot invoke unsupported methods. Resource-bearing operations
require the additional resource capability and acceptance checks.

Syntax IDs and LSP document IDs are distinct: `tsx`/`typescriptreact`,
`jsx`/`javascriptreact`, `shell`/`shellscript`. S1's 31 syntax IDs remain the
authoritative local metadata. Custom servers keep arbitrary document-language
IDs. Polaris-owned keys retain slug grammar; server registration/annotation IDs
are opaque bounded strings. Invalid map keys fail rather than disappearing;
valid environment names including `_JAVA_OPTIONS` survive decoding.

Catalog integration IDs are `typescript`, `html`, `css`, `python`, `bash`,
`java`, `php`, `go`, `rust`, `lua`, `sql`, `prisma`, `yaml`, `actions`.
Python composes Pyright and Ruff with separate diagnostic ownership; YAML and
Actions expressions are separate providers. There is one deterministic selected
formatter. SQL uses sqllens for offline dialect/static-schema editing and
sql-formatter independently; legacy sql-language-server is evaluation-only.
PHP/Lua formatter configuration and developer prerequisites remain explicit.
Advertised server capabilities must be distinguished from exercised features.

Format-on-save defaults on across every save entry point. Formatting failure
still saves current text and reports an error; disk failures remain separate.
Server applyEdit uses the same proposal/acceptance path as actions and rename.
Unsaved text stays in persistent Client drafts and ephemeral language sync,
never in Agent Session history or implicitly written to disk.

## Gate separation and release conditions

G1 publishes shared contracts. A1 now owns the artifact review previously
attached to G1; this sequencing correction permits independent implementation
while preserving every required integration and artifact release condition.
I1 depends on both G1 and A1, and final G4 additionally depends on A1.
G1 grants no distribution policy exception, installation or activation approval.

The merged K1 catalog has 18 offered tools and one evaluation-only tool.
Its strict release check deliberately fails with 13 offered audit blockers.
K2 owns the remaining native/transitive notice/source/build closure. Its current
uncommitted evidence and reviewed packaging proposals are not accepted Claims.
Missing evidence remains blocked; completed review-required records are
assessed at A1 against their exact immutable roots. General license policy is
unchanged. No tool may become ready merely because its descriptor is present.

Optional `Artifact.packaging` preserves K2's `lua-core-v1` contract, including
source, manifest and output integrity plus disabled third-party discovery.
Installers must verify all three and retained legal/runtime closure. This field
is an interoperability contract, not approval of any filtered artifact.
