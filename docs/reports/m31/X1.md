## Delivered interface and behavior

`apps/daemon/src/files/index.ts` exports `createFileEditCoordinator`,
`CoordinatorOptions`, `DraftReceipt`, `Owner` and typed `FileEditFailure`.
`files/edits/README.md` documents the complete integration contract and supported
options. `accept`, `get` and revision-guarded `recover` use the accepted P1
proposal/acceptance/outcome shapes. G2 injects authenticated owner, current
context/document fences, accepted preview and verified durable Client draft
receipt. Authorization is repeated inside canonical resource locks after any
wait. Text edits are never Host disk writes. Nothing registers handlers or
advertises runtime capabilities in this change.

Every resource path has one exact canonical snapshot. The complete ordered
chain is planned before checkout mutations. Original `documentChanges` indexes
survive interleaved text changes. Regular-file creates stage empty files;
renames preserve bytes/mode/mtime; deletes move into private operation backups.
Overwrite backs up its target first. Ignore options produce explicit no-op
steps; overwrite takes precedence. Missing rename sources, ambiguous text forms,
stale/missing/duplicate snapshots and canonical aliases are refused.

Owner/operation identity and request fingerprint provide durable acceptance
idempotence. Identical retries return the existing result, including applying,
partial and restored states; a different request with the same ID fails.
The sorted existing `withFileMutation` queue serializes overlapping operations.
Prepared journals/staged files are synced before forward moves. Each move
persists forward intent, checks exact source and destination absence, renames,
syncs both affected directories, and persists applied state. Final acknowledgment
requires durable Client drafts and an applied Host receipt. Atomic receipt
replacement and directory fsync precede returned results; revisions increase.

Recovery reverses moves, reconciling durable intents with actual exact versions
at source/destination. It persists reverse intent and restored receipts, and
can restart during recovery. Undo/cancel/recover never resume stale forward
application. Intervening versions or occupied owned absences prevent reversal;
remaining backups are retained and outcome is `recovery-required`. A partially
successful reversal identifies the conflicting original change and steps
already restored. Stale receipt revisions fail without disk changes; query
again after a lost recovery response. Unjournaled pre-prepare staging is discarded
only for the same private owner/operation directory before a fresh acceptance.

## Supported boundary and owners

X1 is a regular-file foundation per Lead clarification. Directories, including
empty directories, leaf symlinks, special files, non-file URIs, checkout escapes,
and `recursive:true` deletes fail closed. Parent symlinks are canonicalized and
canonical parents are revalidated at mutations. Journal roots are Daemon-owned,
canonical, outside the checkout, and must be on the same filesystem.

X2 owns protocol-first bounded no-follow tree manifests and recoverable directory
create/rename/delete, source and overwrite-target descendant ownership, root/tree
races, dirty descendant drafts and tree recovery. It must use a dedicated
snapshot contract rather than overload regular-file `FileVersion`. G2 depends
on X2 and X1 before resource capability activation. G2/R1 own authenticated
transport, generation/fence and verified durable draft receipt wiring; X1 cannot
certify those paths independently. No protocol or peer-Area changes were made.

This is recoverable sequencing, not filesystem-wide atomicity. There is no OS
compare-and-rename primitive; external mutation between the final check and
rename has the existing versioned-save race boundary. Cross-filesystem rename
fails safely but can leave earlier moves partial. Exact ownership uses the
accepted mtime/size/SHA-256 version, not a history oracle. Private journals are
trusted Daemon state. Disk-full/fsync failures may leave only an earlier durable
receipt: report unknown outcome, query, never acknowledge in-memory success.
Backups/terminal receipts intentionally remain for unknown outcomes and undo;
future retention/quota policy must not prune unresolved recovery. No timers,
watchers, global scans, downloads or idle work were introduced.
