# K1 — catalog descriptors, prerequisite policies and artifact evidence

Assignment: K1, branch `m31/k1`, retained implementation base
`ad42eb7fadd14e060c5af5e4349c4f2c71583e58`.
This report describes implemented descriptor/audit machinery and live disposable
packaging evidence. **The whole catalog is not release-ready.** Thirteen offered
tool records have explicit activation blocks. Legacy SQL is evaluation-only. The
strict gate preserves incomplete notice and external-policy blockers for K2/G1.

## Delivered interfaces

- `apps/daemon/src/languages/catalog/index.ts`: validated catalog and public
  model/selection/verification exports; no running-Daemon wiring or timer.
- `model.ts`: exact tool/artifact versions, OS/architecture/libc, immutable
  integrity/audit roots, runtime/project prerequisites, provider launch entries,
  formatter/diagnostic ownership and trust/network policies.
- `selection.ts`: `selected`/`unsupported-platform`, numeric minimum-version
  checks, and phase-separated `eligible`/`missing-prerequisite`/`audit-required`
  outcomes. Eligibility is neither installed nor ready.
- `verification.ts`: SHA256/SHA512 verification, traversal rejection and
  independently pinned notice manifests. Altering/omitting a notice or manifest
  fails; installers must independently reject escaping archive links.
- `tooling/language-catalog/`: original frozen npm locks and verified package
  roots, verbatim legal files, Cargo/Go/JAR/PHAR/source inventories, external
  review records, consistency/strict gates and opt-in fixture scripts.

No outside-Area files changed. No production manifest/lock, real project,
`~/.polaris`, SSH/account configuration or developer runtime was installed or
modified by the catalog tooling. Root checks operate on temporary fake fixtures;
replacement checks use no global Git configuration; fixture children receive an
allowlisted environment with per-tool config/cache paths and no HOME override.

## P1/I1 handoff requirements

P1 must represent Host installation facts separately from local Editor settings:

1. Catalog/tool/provider/artifact IDs, exact pinned version, active installed
   version, platform/libc, artifact/audit roots, update candidate and actual
   capability facts. `audit-required` is a failure reason, not ready/installed.
2. Prerequisite facts with requirement ID, scope, effective Host executable,
   detected version, missing/incompatible reason and explicit refresh. Install
   phase checks server/build prerequisites; feature phase also checks project
   SDK/interpreter/toolchain. Never install those developer-owned prerequisites.
3. Per-Host/tool/version deduplicated install progress and staged activation.
   Preserve working versions on failure/update and switch between sessions.
   I1 must embed/transfer the exact bundles, hash every dependency and notice,
   disable lifecycle scripts, keep private install/build/cache roots, and honor
   pending audit/source-delivery/G1 review records. No production wiring exists
   yet; the immutable tooling snapshots are installer inputs.
4. Effective provider launch entry/argv/environment distinct from shared tool
   installation; HTML/CSS have separate entries. Deterministic diagnostics,
   action/completion routing and **one** selected formatter. PHP/Lua configurable
   formatter absence is explicit; unsupported capabilities stay unsupported.
5. SQL dialect/static-schema settings, plugin-disabled/explicit-config policy,
   no account/database credentials or execution. Actions no sessionToken.
   TS actual SDK resolution is distinct from project plugin probe roots (F1).
6. Awaiting trust, installing, installed-but-missing-project-runtime, ready,
   stopped/failed/unsupported and update-available remain separate facts; this
   catalog's `eligible` result is only preflight, never a lifecycle transition.
