## Delivered boundary

The core constructs only when explicitly given a canonical, private,
current-user-owned root, a Host/platform, and download/decoder adapters. There is
no default `~/.polaris` root, HTTP client, archive CLI, runtime probe, execution,
RPC handler, capability advertisement, timer while unused, or production import.
Every artifact in the tests is synthetic; no upstream package code is copied.

`install/index.ts` exports `createInstaller` and its `Installer` result.
`install/types.ts` supplies `InstallerOptions`, `InstallerAdapters`,
`ExactArtifact`, `ApprovalDecision`, `ArtifactPayload`, `InstallRequest`,
`InstallHandle`, `InstalledVersion`, `InstallLimits`, and `Progress`.
`install/service.ts` supplies the scoped `ManagedInstaller.layer(options)`.
`availability/index.ts` exports `availability` and `AvailabilityInput` using
accepted P1 wire schemas. Imports below are relative to the Daemon language
folder; consumers must use the exact accepted I0 commit.

```ts
import { createInstaller } from "./install/index.ts";
import { ManagedInstaller } from "./install/service.ts";
import { availability } from "./availability/index.ts";
```

Promise construction is asynchronous and validates the root. Methods:

- `install({tool, probes, connected, intent})` returns `{jobId, result, cancel}`.
  `intent` is `encounter`, `install`, or `update`. A different selected version
  requires `update`; ordinary demand never silently upgrades or downgrades.
- `rollback({tool, probes, connected})` selects an existing verified private
  version through the same exact approval/session barrier, without downloading.
- `current(toolId)` and `versions(toolId)` validate stored receipts and file
  hashes/tree containment. These are installation facts, not launch certificates.
- `subscribe(listener)` returns an unsubscribe function. `progress(toolId)`
  returns a defensive snapshot. Sequences increase within each job. Observer
  exceptions cannot alter installation outcomes.
- `stats()` exposes bounded jobs/waiters/observers/progress and failed lock
  cleanup job IDs. `dispose()` aborts and awaits owned jobs, clears observers and
  progress, and creates no background poller. Cancel detaches only one consumer;
  the final consumer aborts the shared job.

The Effect service exposes install/rollback/current/progress/subscribe; scoped
Layer release calls `dispose`. Effect interruption cancels that consumer rather
than a peer's shared installation. Use one installer instance per Host/root.
Concurrent exact Host/tool/version/descriptor requests share a job. Other
versions or operations on the same tool are rejected with retryable conflict;
there is no unbounded queue. A private exclusive lock prevents two constructed
instances from publishing to the same tool concurrently; cross-instance conflict
is explicit, rather than pretending they share a Promise.

## Approval, prerequisites and future metadata

An omitted approval adapter always denies before downloading, including tools
whose catalog audit says verified. Approval receives a defensive complete
`ExactArtifact`: Host, selected platform, validated tool/artifact, raw JSON
`descriptor`, and canonical SHA-256 identity. A positive decision must return
that exact identity. Identity includes all raw tool metadata and selected artifact
ID; changing future metadata, version, platform, integrity, audit root, packaging,
notices root, or Host requires a different decision. Reordered JSON object keys
preserve identity. The core checks approval again after staging and before
publication. Neither that callback nor a passing test grants A1/user approval.

Protocol-known tool fields are schema-validated; the original JSON descriptor is
retained separately in approval requests and immutable receipts. In particular,
future optional `developerCompanions` metadata is not stripped. I0 does not invent
or enforce the pending A1 protocol additions. I1 must interpret the accepted
A1 companion/prerequisite contract and approve only complete exact evidence.

Platform/offered disposition/server prerequisites and Connection facts deny
installation early. Probe facts are injected observations; the core does not
execute a probe or install a runtime, compiler, project dependency or companion.
Availability separates installation from feature preflight, including project
requirements, missing/incompatible/unknown facts, offline, unsupported platform,
awaiting trust, pending installation, retained failed-update version and explicit
update candidate. Availability approval defaults false. `approved:true` is an
injected observation and is never consulted as authority by the installer.

I1 must provide `beforeSelect(exact, signal)` as its between-server-sessions
barrier. Its rejection retains the working version. The detached core has no
running servers and the synthetic tests use either no barrier or a fake barrier.
Launch trust/feature prerequisites remain D1/T1/I1/G2 responsibilities.

## Integrity, extraction and publication

The core collects bounded bytes, verifies the pinned SHA-256/SHA-512 integrity,
then calls a pure injected decoder. No subprocess or package lifecycle script is
run. The decoder cannot receive a private installation path. It must honor the
AbortSignal and bound parser allocation/expansion while decoding; a typed adapter
is not a certification of a production tar/npm/gzip/parser implementation.

Before any file is written, the core checks every entry: relative canonical NFC
paths, no traversal/absolute/drive/backslash/NUL/empty/dot components, no duplicate
or case-aliased paths/prefixes, no file/directory prefix collisions, no special
permissions, and bounded bytes/count including implicit parent directories.
All symlinks and hardlinks are rejected, including links in a filtered-out tree.
This deliberately conservative link policy satisfies containment; adapters must
not silently follow or materialize a real archive's links as files.

Notices come from the pinned audit manifest, which must match the artifact/audit
root and complete coverage. Manifest bytes/counts, unique notice paths and retained
notice file hashes are checked. Lua packaging additionally verifies pinned source,
manifest and post-filter file/mode roots, template/core coverage, excluded-tree
absence and disabled third-party discovery. Required notices are checked again
against the filtered output, so filtering cannot discard a required notice.

Each tool has owned random staging, immutable identity directories with `payload`
and receipt, and an atomic `active.json` pointer. Files/receipts are written with
exclusive creation and file fsync; version publication and pointer selection use
same-filesystem rename. The previous version remains until pointer replacement.
Publication failure removes only this job's staging/new unpublished version,
not existing versions or unrelated files. Readback checks Host/platform/descriptor
identity, complete tree coverage, expected entry, hashes, regular owned files,
no links and no changed/unlisted entries. Existing versions are validated before
reuse; corruption never becomes an installed/ready certificate.

Cancellation checked before issuing pointer rename prevents publication. Issued
atomic pointer replacement is the commit boundary: cancellation after it cannot
retract a successful selection. Disposal awaits owned filesystem operations;
the deadline interrupts pure adapters and checks write/selection boundaries,
rather than claiming to cancel an operating-system syscall. Consumer cancellation can detach before shared
completion; the job still owns cleanup until settlement. No filesystem-wide
atomicity or power-loss durability is claimed (parent directory fsync/crash
journal/recovery is not implemented). Old versions are retained for explicit
rollback; no automatic pruning or stale-lock stealing occurs. Cleanup inability
raises `recovery-required`; failed lock cleanup appears in stats. I1 must surface
and recover those owned facts, never delete uncertain active storage.

Default caps (only lower overrides allowed): 32 MiB download, 64 MiB expanded,
16 MiB per file, 4096 logical/physical entries and download chunks, 1 MiB
metadata/receipt, 16 retained versions per tool, 4 jobs, 64 consumers and observers,
120 s job deadline, 256 last progress records and 64 failed cleanup records.
Version-cap rejection retains existing versions. Arbitrary same-user hostile
filesystem replacement during syscall gaps is outside this private-root model;
no OS-level directory-handle sandbox or remote Host certification is claimed.

## I1/G2 recipe and remaining gates

1. Consume the exact accepted I0 head, not a moving branch. Construct one Host
   instance in an authenticated private canonical root; install no runtime.
2. Consume exact accepted A1 artifact/notice/packaging/developer-companion evidence.
   Supply an identity-bound approval adapter that defaults deny on any missing
   or changed evidence; no real catalog download/installation/activation before A1.
3. Supply certified bounded download/decoder adapters with cooperative transport
   cleanup. Do not execute package scripts or let extraction write arbitrary paths.
4. Inject current prerequisites/Connection facts, coordinate explicit updates and
   between-session selection, map progress/availability to optional LanguageRpcs
   and IPC without advertising incomplete capabilities, and gate launch on trust.
5. Dispose on Host service shutdown; observe typed failures and cleanup stats.
   Add crash/stale-lock/retention recovery and platform integration tests, then
   measure actual resource budgets and finish I1/G2 certification.

No central wiring, catalog edits, dependency changes, developer-toolchain install,
real environment/account/Sightline/SSH mutation, protocol/spec edit, or production
activation occurred. Existing protocol/Engine/store/resume decisions are unchanged;
no detached installer fixture is represented as a model proof or runtime trace.
