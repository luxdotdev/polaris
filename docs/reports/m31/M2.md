# M2 — Markdown source and rendered views

## Scope and seam

M2 integrates the accepted M1 renderer into the real Editor, on base
`4710ae39d744ab35e2e7a199a46c9e54742b018b`. Source opens by default. The shared
keymap adds `editor.markdownPreview`, Cmd+Shift+V, also shown in the native View
menu through its existing keymap adapter. The command is enabled for Markdown.

`model/tabs.ts` retains `TabSet.active` as the underlying file path. Optional
`activeView: "markdown"` selects the rendered view. Source identity is its path;
`tabId(rendered)` is `markdown-preview`, one following/lockable view per
Workspace. The existing `Tab.preview` remains the unpinned-source replacement
flag. Source and rendered tabs share `viewOf(fileKey(hostKey, path))`, including
unsaved text, undo, selection, drafts, disk versions and watches.

Closing either view keeps the buffer while another view or Workspace shows it.
The last dirty view uses the existing Save / Don't save / Cancel dialog. A
captured close `viewId` is fenced against a retargeted preview. Following away
from a dirty rendered-only file retains a pinned source tab, preserving history
and quit/save visibility. Renames retain rendered identity and lock state.

`model/drafts.ts` adds optional validated view/lock/active fields to the existing
local tab record. Legacy source-only records retain their exact structure.
Unknown fields and malformed new values are rejected rather than stripped.

## Renderer and policy ownership

`ui/MarkdownHost.tsx` lazily loads M1. A frame-coalesced observer reads the
existing CodeMirror state, including detached updates and disk reloads. One
weakly held compartment per view is reused across mounts; closing cancels the
pending frame and removes its listener. No new polling or duplicate text store.

`runtime/markdown.ts` resolves real Host and registered Workspace, Worktree or
Review Checkout facts from the Host model. Relative links use the shared Editor
open path; local fragments remain in preview. Media uses C1's optional typed
LanguageApi. Reconnecting/Offline or older Hosts keep source rendering and show
unavailable media. Connection epoch changes remount the media pool, retiring old
URLs and pending resources. Authenticated canonical containment, DNS and policy
validation remain in main/Daemon; this renderer does not grant that authority.

`runtime/actions.ts` exports `refreshMarkdownPolicy(hostKey, workspaceId)` for
U1. Call it only after confirmed matching policy.set success. It increments a
local per-Workspace preview epoch, remounting the policy/media pool. No refresh
on unknown, cancelled or failed results, no cross-Workspace invalidation and no
policy polling. Lead recorded this exact integration responsibility in U1.
