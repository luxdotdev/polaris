Polaris on Windows gets its own daemon: agents run on This PC, on other Windows PCs over SSH, and in WSL.

## What's new

### Windows

- **This PC.** The x64 Windows app now has a local host. It carries its own daemon and installs it the first time you open Polaris, with no administrator and no window. Terminals, git, files and agent sessions all run on your PC, and paths read the Windows way (`C:\`, `~` for your home).
- **A sign-in task.** This PC's daemon starts when you sign in to Windows and restarts itself within a second if it stops. If another Polaris home already holds the task, the hosts list says which one and offers **Take over sign-in task**, which tells you what stops before anything does.
- **Windows PCs as SSH hosts.** Add a Windows PC running OpenSSH Server as you would a Mac or Linux machine. Polaris installs and upgrades its daemon over PowerShell, pwsh or cmd, whichever the PC's ssh uses, with no administrator.
- **WSL hosts.** Checked on WSL 2.7. A distro that just woke up connects on the first try, a removed distro says so instead of retrying, and finding distros works in any Windows display language and without WSL installed. A WSL host's settings no longer offer ssh-agent forwarding, which WSL doesn't use.
- **Claude Code from npm.** A Claude Code installed with npm now starts agent sessions, inline edits and commit messages on Windows, as the native installer's does.
- **Long paths.** Git on Windows works in deeply nested workspaces, and constellation workers on a Windows host no longer fail with "Filename too long".
- **Codex on Windows.** Codex runs on Windows hosts. Its server listens only on your PC, answers only with a token only your account can read, and stops with the daemon.

### Constellations

- **Accept merges for you.** Accepting a claim merges it into the lead's checkout; you no longer merge by hand first. If the checkout has changes, isn't on a branch, is mid-merge, or the merge conflicts, Accept says which and leaves the checkout clean.
- **Claims can change in review.** A worker can amend its claim while you review it. Review shows "amended from" the old commit and turns Accept off until you open the new one, so you only accept what you saw.
- **Worker questions reach needs you.** A worker's question to you stays in **Needs you** until you answer it, even while its claim is in review, and closes when its attempt ends.
- **Stalled workers and Start.** A worker that holds its slot for over a minute without starting reads as stalled, needs you, and offers **Start**. A worker whose setup a restart interrupted runs its setup again and starts.
- **Lead status.** The lead's status shows each worker's setup, turn and slot, who is waiting for the host's slots, who sent a claim back and why, and the id of each worker question.

### Conversations

- **MCP calls and skills read like the rest of a turn.** A run of tool calls now reads "Loaded grilling, ran 1 command, called Paper 4 times" instead of raw tool names and JSON. Expand it to see each call with its arguments and a short result, and **Show raw** for the rest. A failed call or one waiting for approval stays outside the run.

### Security

- **This PC's daemon is checked before Polaris talks to it.** On Windows, the app and SSH connections only speak to a daemon your own account started. If another account holds its pipe, the host says so and nothing is sent.
- **A repository can't swap in its own programs.** On Windows, a `git.exe` or other program committed to a repository could run in place of your own. The daemon now runs git, shells, agents and every other program by its full path.
- **Signed merges.** When your git config signs commits, Accept signs its merge with your own key and program, never ones the repository's config names.
- **Passed checks are real.** A check in a claim shows as passed only when it points at a command the agent ran. Another tool's output can no longer pass for one.

### Fixes

- **Security keys over ssh on Mac.** Polaris uses the ssh from your login shell, not Apple's, so `ed25519-sk` and other security keys work when you open Polaris from the Dock.
- **One failed request stays one.** An error in one request no longer drops the whole connection to a host. Polaris also reconnects at once to an older daemon that drops it.
- **Steering keeps attachments.** A draft with attachments queues as a follow-up instead of leaving them behind, and the working strip clips a long command rather than squeezing its timer.
- **Bun 1.4.3.** The daemon runs on Bun 1.4.3, which brings terminals to Windows.
- **Steadier under load.** A host's daemon no longer stalls its worker slots when the machine is busy, and a cancelled request stops the git it started instead of leaving it running in your repository.
- **File changes on Mac.** A workspace's file tree and search no longer miss a change made just as they start watching.
- **Two games.** Type "space invaders" or "pong" in the command palette.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.2.0-arm64.dmg` and drag Polaris to Applications, then open it. The app is signed and notarized, so macOS opens it without a warning.

- **On 0.1.0,** Polaris updates itself. Choose **Restart to update** when it says 0.2.0 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.2.0-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.1.0,** Polaris updates itself. On an x64 PC, This PC then appears and installs its daemon. If yours doesn't update, install this release by hand.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts, on by default), Polaris upgrades each host's daemon the next time it connects, and working agent sessions carry on. A host Polaris hasn't connected to stays on its old daemon until it does. Until a host runs 0.2.0, Accept there still needs the claim merged by hand, **Start** doesn't work, and a worker's question can still drop out of **Needs you**.

You'll also need at least one agent, like Claude Code or Codex, installed wherever you want agents to run.

## Known limitations

- **Windows is unsigned and still new.** CI only smoke-tests the x64 installer.
- **ARM PCs have no This PC yet.** The arm64 app connects to other hosts only, and Windows hosts must be x64.
- **Some tools are off on Windows hosts.** No language tools in the editor (highlighting works), no secret scanning in the risk summary, and no edit prediction model on the PC itself. With Claude Code, the reviewer reads files but can't run checks. OpenCode's **Open in terminal** doesn't work there.
- **Upgrading a Windows host ends its terminals.** Agent sessions recover, and the app tells you once that the terminals ended.
- **A Windows host's daemon runs only while you're signed in to Windows.** Over SSH alone, sign in at the PC first.
- **Windows has no trash.** Deleting a file in the editor on a Windows host asks first, then deletes it for good.
- **Lead status doesn't see slots on remote hosts yet.**
- **On a Mac host, opening or closing a file or workspace can make another open one miss a change.** It shows up at the next change. A fix is planned for 0.3.0.
- **Mac app is Apple silicon only.** Linux machines (x64 and arm64) work as hosts, not as a desktop app.
- **A host's own downloads don't use a corporate proxy's certificate yet.** Language servers and the edit prediction model download on the host, which doesn't yet trust a certificate a tool like Zscaler installs.
- **Edit predictions are tuned for TypeScript.** Other languages get suggestions without the language-server check.
- **A Raspberry Pi 4 doesn't serve completion.** Point it at a model server on a larger machine.
