The fourth Polaris alpha: tab completion that suggests edits, not just insertions, and sets itself up. It's for testing: expect rough edges, and tell us what breaks.

## New in this alpha

- **Edit predictions.** Tab completion now suggests the next edit near the cursor and elsewhere in the file: a rename carried through, a call site updated, a line you were about to delete. Tab accepts; Esc dismisses. Before a suggestion shows, Polaris checks it against the language server and drops any that would add an error.
- **One-click setup.** Turn on tab completion and Polaris downloads Sweep Next-Edit 1.5B (1.5 GB) to the machine that serves completion, checks it against its published checksum, and runs it there. The model server starts on your first keystroke and stops after 15 idle minutes. You can choose where the model is stored, including an external drive. Zeta 2.1 is available as a higher-quality option that uses more memory. A model server of your own still works and is used first.
- **Missing imports.** When an edit uses a name that isn't imported, Polaris offers the language server's import fix as a suggestion.
- **Settings for edit predictions.** Display (Full, or Subtle with ⌥ to preview), Aggressiveness (how far suggestions reach), the accept key, languages to leave out, and Clear history.
- **A status card that shows how completion is doing.** The model and what it can do, latency, the model's load time (shown separately, not counted in latency), and how often suggestions are accepted and undone. The counts are kept on this machine and never uploaded.
- **TypeScript 7.** TypeScript and JavaScript now use TypeScript 7's language server by default: faster, and about half the memory. Trusted projects on TypeScript 6 or older, or with tsserver plugins, still use typescript-language-server. TypeScript 7 doesn't offer refactors like Extract function yet.

## Also in it

- **Pull and push** from the status bar and the Changes tab.
- **Changes made outside Polaris** (a commit in your terminal, a branch switch) reach the Changes panel and open diffs.
- Fixes for file watching on Linux, menus with two-line options, and the setup screen when no host exists.

## Installing

These builds aren't signed yet, so macOS and Windows will warn you the first time.

**Mac (Apple silicon).** Download `Polaris-0.1.0-alpha.4-arm64.dmg` and drag Polaris to Applications, then open it. macOS will refuse the first time. Open System Settings → Privacy & Security, scroll to the message about Polaris, click **Open Anyway** and confirm. On macOS 14 and earlier, right-click Polaris in Applications and choose **Open** instead.

**Windows.** Download `Polaris-0.1.0-alpha.4-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

You'll also need at least one agent, like Claude Code or Codex, installed wherever you want agents to run.

## Known limitations

- **No automatic updates between alphas.** Prereleases aren't on polaris.lux.dev or its update feed, so install the next alpha from this page by hand. The unsigned Mac app can't update itself at all, so checking for updates on a Mac says "Couldn't check for updates".
- **Unsigned.** Gatekeeper and SmartScreen warnings are expected until signing is set up.
- **Mac app is Apple silicon only.** Linux machines (x64 and arm64) work as hosts, not as a desktop app.
- **Windows is experimental.** No local host, and CI only smoke-tests the x64 installer.
- **Edit predictions are tuned for TypeScript.** Other languages get suggestions without the language-server check.
- **A Raspberry Pi 4 doesn't serve completion.** Point it at a model server on a larger machine.
