You can now share an agent session with a teammate. They watch it live from their own desktop app or iPhone, comment on messages and diff lines, and, as a contributor, send turns and answer approvals, while the work stays on your host. This release also adds **Origins**, which traces a line of code back to the agent session and turn that wrote it, and turns approvals back on for processes on your hosts, with a way to allow each of your desktop apps.

## What's new

### Shared sessions

- **Share from the session header.** **Share** opens the share sheet: enter a teammate's GitHub handle, pick contributor or commenter, and how long the share lasts (7 days by default, renewable up to 30).
- **Two roles.** A **commenter** watches the session and comments. A **contributor** also sends turns, steers, edits the queue, answers approvals and accepts turns. Archiving, terminals, writing files, reverting turns and managing the share stay yours.
- **Your host decides.** A teammate reaches your host through the Polaris Relay, end to end encrypted. Polaris accounts only vouch for who they are (GitHub sign-in); the host checks every request against your shares, and revoking cuts them off at once. The share sheet keeps a log of invites, joins, new devices, renewals and revokes.
- **Shared with you.** Sessions others share with you sit in their own section of the sidebar, grouped by owner, with your role and whether their host is reachable. Avatars in the header show who's watching.
- **Comments.** Select text in a message or a diff line to comment. Comments are part of the session, so everyone on it sees them, can resolve and reopen them, and can send them to the agent as feedback.
- **A shared queue.** Queued turns show who wrote them; anyone who may send turns can edit or cancel them. Interrupting pauses the queue and **Resume** starts it again. A queued turn checks its author may still send when it starts.
- **Needs you reaches contributors.** Approvals go to every contributor's devices as well as yours, and the first answer wins. A teammate's **Allow** holds for that request only.
- **Credit in commits.** Commits from a shared session carry `Co-authored-by` trailers for the teammates who contributed.
- **Accounts.** Settings → Polaris accounts signs in with GitHub. The desktop app and the iPhone can hold more than one account, and a team can run its own account server instead of Polaris's.

### Origins

- **Why is this line here?** Inline blame on the cursor's line names the agent session that wrote it. Its hover card lists the commits, sessions and turns behind the line, from every connected host; an offline host shows as offline. Session rows open at their turn, commit rows open their diff. A setting and a command turn inline blame off.
- **For agents too.** The `origins` tool takes a line range or a commit and returns the sessions and turns behind it, with excerpts of the prompt and reply. `read_history` opens a turn by its id.
- A host indexes the lines each turn added as the turn's checkpoint is recorded, and backfills older turns once in the background.

### Your hosts

- **Approvals need one of your desktop apps again.** 0.9.2 turned off the protection that stops any process on a host, an agent's own shell included, from approving its own requests. It's back: approving, sending turns, starting agent sessions, reading files and the other user-only actions need a desktop app the host has allowed.
- **Allow each desktop app.** The first desktop app to connect to a host is allowed. Another one asks, and every allowed desktop app shows "Allow ‹device› on ‹host›?" with a short code that matches the one on the asking app. Settings → Hosts lists the allowed desktop apps on each host's page, with **Revoke**; the last one can't be revoked.

## Installing

**Mac (Apple silicon).** Download `Polaris-0.10.0-arm64.dmg` and drag Polaris to Applications, then open it.

- **On 0.9.2 or earlier,** Polaris updates itself. Choose **Restart to update** when it says 0.10.0 is ready.

**Windows.** The Windows build still isn't signed, so SmartScreen will warn you the first time. Download `Polaris-0.10.0-x64-win-Setup.exe` (or the `arm64` one for ARM PCs) and run it. When SmartScreen says "Windows protected your PC", click **More info**, then **Run anyway**.

- **On 0.2.0 or later,** Polaris updates itself.

**Your hosts.** With **Keep daemons up to date** on (Settings → Hosts), each host moves to 0.10.0 the next time it connects. Sharing, Origins and the desktop app allowlist need the host on 0.10.0. A host that already has a desktop app connected keeps it allowed; any other desktop app asks once.

## Known limitations

- **Sharing needs Polaris accounts online.** Signing in uses `auth.polaris.lux.dev`, which goes live shortly after this release. Until then, **Sign in** in Settings → Polaris accounts fails, and nothing can be shared.
- **Shared sessions:**
  - A teammate's steer doesn't show who sent it, and isn't credited in commits (ENG-961).
  - Changing a teammate's role means revoking and inviting them again (ENG-960).
  - The desktop app's presence row includes you (ENG-958). Some older copy still capitalizes words like agent session (ENG-959).
  - A desktop app or iPhone older than 0.10.0 signed in to two accounts may show a shared host twice (ENG-963).
  - Sharing on the iPhone is in TestFlight builds only.
- **Origins** is in the desktop app only (ENG-933), and finds the latest commit for a line, not earlier ones (ENG-935).
- A few host requests that aren't pure reads stay open to processes on the host without a desktop app: leases, `git status` and some watches (ENG-953).
- 0.9.2's [known limitations](https://github.com/luxdotdev/polaris/releases/tag/v0.9.2) still apply, apart from approvals being open to processes on the host.
