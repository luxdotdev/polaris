# Codex Security scan, October 2026

A Codex Security scan of the repository on 15 October 2026 reported 28 findings: 10 high, 12 medium, 6 low. Several are the same issue found from different entry points; [README.md](README.md) groups them, one row per issue.

## Areas

- **Worktree setup**: a dispatched worker ran a repository's lockfile install scripts before any trust decision, with the Daemon's whole environment. Setup now runs only in Workspaces the Host trusts, with an allowlisted environment.
- **Automatic git**: git the user didn't ask for (status, diffs, snapshots, Review fetches, the Rules layer) ran commands a prepared repository's config names, and its output was unbounded. It now runs with a fixed safe config and bounded output (ADR 0056); Polaris-made worktrees never run hooks.
- **Review Run and the Reviewer**: a pull request's own scripts got the Daemon's credentials, and the Reviewer could read outside its checkout. Review Checkout terminals get an allowlisted environment (ADR 0054), and the Reviewer is confined to its checkout, with a default-deny hook and an OS sandbox (ADR 0055).
- **Desktop App**: oversized editor reads, paths outside the Workspace, malformed review links, and preview images whose decode cost far exceeded their size. Images are now measured before decoding (ADR 0058), and every Mermaid render refuses images.
- **Remote install**: the Host's daemon download is bounded and staged privately.
- **Release**: external Actions are pinned to commit SHAs, and signing runs apart from the build (ADR 0057).
- **Download email**: one reply for every address, and deployment-wide limits and cooldowns.
- **Nucleo licence**: accepted by the owner; not a vulnerability.

## After the fixes

Adversarial agents probed each fix; their bypasses were fixed in follow-ups (GIF canvas cost, the JPEG gain map, the Reviewer's git config, Mermaid images, IPv6 rotation). While writing the regression guards, three more gaps in automatic git turned up and were fixed in `edb87666` and `07842e3a`: a partial clone's lazy fetch ran a remote's upload-pack on any read, and the Rules layer's `cat-file` and Betterleaks' `git log` ran without the safe config.

The guards in [README.md](README.md#guards) fail when new code goes around a fix: lint rules with commented allowlists for git spawning, git's host config, image decoding and repository-code environments, plus tests that external Actions stay pinned and that Main's bare `fetch` stays a lint error.

Open owner actions: the Upstash store, a Vercel Firewall rule and SES alarms for the email endpoint; required reviewers and tag rules on the `release` environment. See each row's residual column for the rest.
