# Attribution

Code that Polaris **copies or adapts** from other projects, as opposed to depending on them (dependencies are listed in `THIRD_PARTY_NOTICES.md`, generated by `bun run licenses`). Every file containing borrowed code also carries a header naming its source.

Each entry records the source repository, the pinned commit, the licence, the Polaris files it landed in, and what changed.

## Designs followed (no code copied)

- **pingdotgg/t3code** @ `de251fc` (MIT): the protocol shape (snapshot then sequenced, resumable streams; `afterSequence`), the event-sourced store with command receipts, and per-Turn git-ref checkpoints. `packages/protocol`, `apps/daemon/src/store`.
- **tty7** (Apache-2.0): user-service install with SHA approval, capability-negotiated versioning, and the `execve` upgrade hand-off.
- **herdr** @ ≥ `cd5ea1be` (Apache-2.0): the OpenSSH stdio bridge and reconnect model.

## Copied or adapted code

- **openai/codex** `codex-rs/app-server-protocol`, as shipped in codex-cli `0.157.1` (Apache-2.0): TypeScript bindings generated by `codex app-server generate-ts` (ts-rs output from the upstream Rust types). They landed in `apps/daemon/src/harness/codex/generated/**`. Changes: only the import closure of the types the Codex driver uses is kept (via `generate.ts`), each file gets a provenance header, and Biome reformats them. The runtime schemas in `apps/daemon/src/harness/codex/protocol.ts` are hand-written against these types.
- **pingdotgg/t3code** @ `de251fc` (MIT), design only, no code copied: the Codex permission-mode table (approval policy / sandbox / approvals reviewer per mode) and the handling of async questions as new user messages, from `apps/server/src/provider/Layers/CodexSessionRuntime.ts` and `docs/internals/providers.md`, as summarized in `docs/research/t3-code.md`. They landed in `apps/daemon/src/harness/codex/mapping.ts` and `CodexSession.ts`.
