# Attribution

Code that Polaris **copies or adapts** from other projects, as opposed to depending on them (dependencies are listed in `THIRD_PARTY_NOTICES.md`, generated by `bun run licenses`). Every file containing borrowed code also carries a header naming its source.

Each entry records the source repository, the pinned commit, the licence, the Polaris files it landed in, and what changed.

## Designs followed (no code copied)

- **pingdotgg/t3code** @ `de251fc` (MIT): the protocol shape (snapshot then sequenced, resumable streams; `afterSequence`), the event-sourced store with command receipts, and per-Turn git-ref checkpoints. `packages/protocol`, `apps/daemon/src/store`, `apps/daemon/src/git` (temporary-index working-tree snapshots).
- **tty7** (Apache-2.0): user-service install with SHA approval, capability-negotiated versioning, and the `execve` upgrade hand-off.
- **herdr** @ ≥ `cd5ea1be` (Apache-2.0): the OpenSSH stdio bridge and reconnect model.

## Development tools under other licences

Used as development dependencies only: never copied into Polaris and never shipped in the Daemon or the Desktop App. `bun run licenses` gates production dependencies, so they don't appear in `THIRD_PARTY_NOTICES.md`.

- **eslint-plugin-sonarjs** `4.2.2` (LGPL-3.0-only), pinned exactly in `packages/lint-config`: provides the `cognitive-complexity` lint rule, loaded through a small wrapper (`packages/lint-config/plugins/sonarjs/index.mjs`) that imports the unmodified package.

## Assets under other licences

- **Nucleo icons** (Copyright © Nucleo, Nucleo License, **not Apache-2.0**): 13 UI outline icons (chrome) and 9 pixel icons (Session States and Polaris concepts), vendored into `packages/ui/src/icons/nucleo/` by `packages/ui/scripts/vendor-nucleo.ts` from a licensed install, with `LICENSE.md` beside them and a line in the root `NOTICE`. The pixel hand, terminal and circled x-mark were already in `design/scripts/gen_dither.py` and `design/assets/icons/`. Nucleo allows at most 100 icons in an open-source project with its copyright notice and forbids redistributing them apart from the product; a project decision (2026-09-30) that may be revisited. Changes: the SVG bodies are wrapped in Polaris components (16px, a 1px stroke for UI outline, `currentColor`, `aria-hidden`); no paths changed.

## Copied or adapted code

- **openai/codex** `codex-rs/app-server-protocol`, as shipped in codex-cli `0.157.1` (Apache-2.0): TypeScript bindings generated by `codex app-server generate-ts` (ts-rs output from the upstream Rust types). They landed in `apps/daemon/src/harness/codex/generated/**`. Changes: only the import closure of the types the Codex driver uses is kept (via `generate.ts`), each file gets a provenance header, and they are otherwise left as generated (oxfmt ignores them; the files committed before the switch to oxfmt were Biome-formatted). The runtime schemas in `apps/daemon/src/harness/codex/protocol.ts` are hand-written against these types.
- **anomalyco/opencode** @ `8d05153` (opencode `1.18.33`, MIT): TypeScript types generated from the OpenAPI document `opencode serve` publishes at `/doc`. They landed in `apps/daemon/src/harness/opencode/generated/**`. Changes: `apps/daemon/src/harness/opencode/generate.ts` converts only the closure of the schemas and request bodies the OpenCode driver uses, with a provenance header; otherwise left as generated (oxfmt and oxlint ignore them). The runtime schemas in `apps/daemon/src/harness/opencode/protocol.ts` are hand-written against these types. The test fixture `apps/daemon/src/harness/opencode/fixtures/approval-turn.jsonl` is a recorded event stream from that version, with paths scrubbed.
- **pingdotgg/t3code** @ `de251fc` (MIT), design only, no code copied: the Codex permission-mode table (approval policy / sandbox / approvals reviewer per mode) and the handling of async questions as new user messages, from `apps/server/src/provider/Layers/CodexSessionRuntime.ts` and `docs/internals/providers.md`, as summarized in `docs/research/t3-code.md`. They landed in `apps/daemon/src/harness/codex/mapping.ts` and `CodexSession.ts`.
- **pingdotgg/t3code** @ `ba79610` (MIT): the Plan Limit mappings from `apps/server/src/provider/Layers/claudeUsageLimits.ts` and `codexUsageLimits.ts`: the scales (`get_usage` in 0–100 percent with ISO resets, `rate_limit_event` in 0–1 fractions with epoch-second resets), naming the `seven_day_overage_included` window after the Model `get_usage` lists first, Codex's `primary`/`secondary` positions with 300/10080-minute fallbacks and a monthly allowance on free and go plans, and merging sparse `account/rateLimits/updated` notifications field by field. They landed in `apps/daemon/src/harness/limits/claude.ts` and `codex.ts`. Changes: the output is Polaris's `PlanLimit` (window kind, scope, status, plan) instead of T3 Code's usage rows; payloads are decoded with Effect Schema; Claude reads the server's own `limits[]` rows (with their severity) and the newer `unifiedWindows` on events; other Codex limit ids become scoped limits instead of being dropped; the rollout-log fallback is new.
- **dmmulroy/anti-slop** @ `c44ef22` (MIT): the anti-slop oxlint plugins, vendored from `skills/install-anti-slop/assets/anti-slop/` into `packages/lint-config/plugins/anti-slop/**` (licence in `LICENSE` there). Changes: a provenance header on each `.ts` file; no rule logic changed. Provenance and update steps are in `packages/lint-config/plugins/anti-slop/UPSTREAM.md`. Its `vendor/eslint-stylistic/` is upstream's own adaptation of **eslint-stylistic/eslint-stylistic** @ `435c3ea` (MIT), kept with its `LICENSE` and `UPSTREAM.md`.
- **Effect-TS/effect**, as published in npm `effect@4.0.0-rc.118` (MIT; the version Polaris pins): the RPC transport protocols. `apps/daemon/src/transport/server.ts` adapts the server `Protocol` from `src/rpc/RpcServer.ts` (`makeSocketProtocol`: per-connection client ids, the disconnects queue, defect encoding on a failed encode); `packages/client/src/rpc.ts` adapts the client `Protocol` from `src/rpc/RpcClient.ts` (`makeProtocolSocket`: routing responses to the requesting client by request id, broadcasting a `ClientProtocolError` when the connection fails, the ping loop). Changes: the socket byte stream is replaced by Polaris's framed Wire (one JSON frame per message, blob side-chunks), there is no built-in retry (HostConnection owns reconnecting), in-flight requests are failed before the connection is reported lost, and a BlobChannel is exposed per connection.
- **shadcn-ui/ui** @ `5563a46` (tag `shadcn@4.21.0`, MIT): the `new-york` registry components, added with `shadcn add` and restyled to Night watch. They landed in `packages/ui/src/components/ui/{button,command,context-menu,dialog,dropdown-menu,hover-card,input,popover,scroll-area,select,separator,switch,textarea,tooltip}.tsx`. Changes: Polaris tokens instead of shadcn's palette (DESIGN.md sizes, radii, the Starlight focus ring, no hover transitions), Polaris chrome icons instead of lucide, variants cut to DESIGN.md's (Button: primary, secondary, ghost, danger), shared menu and float styles, a top placement for the jump menu, and no sheet or toggle components.
- **vercel/geist-font**, as published in npm `geist@1.7.2` (SIL OFL 1.1): the `GeistPixel-Square.woff2` font file, copied unmodified into `packages/ui/src/fonts/` with its licence (`GeistPixel-OFL.txt`) for the wordmark only.
- **ccusage/ccusage** @ `0dd85c1` (MIT; npm `ccusage@20.0.26`): the rules for reading Claude Code and Codex logs, from `rust/adapters/claude/src/{lib,paths}.rs` and `rust/adapters/codex/src/{parser,replay,loader,types}.rs`. They are ported to TypeScript in `apps/daemon/src/usage/claude.ts` and `codex.ts`. Claude: which lines count, the token mapping, and dedup on message and request id (session and timestamp without a request id), with sidechain replays and the replacement order. Codex: turning cumulative totals into deltas, the usage field aliases, skipping a fork's replayed parent history (and the rewritten-burst fallback), and cross-file dedup. Changes: the index is incremental over SQLite (byte offsets per file, dedup state in tables rather than in memory), Codex's `gpt-5` Model fallback, auto-review Model timeline and service tiers are left out, and events are bucketed by UTC hour and linked to Polaris Agent Sessions. `apps/daemon/scripts/usage-vs-ccusage.ts` checks the totals against ccusage itself. The pricing rules (1.25× / 0.1× input defaults for missing cache rates, 2× input for one-hour cache writes, per-request long-context tiers, and the fast / priority multipliers from `rust/crates/ccusage-core/src/{cost.rs,pricing.rs,fast-multiplier-overrides.json}`) landed in `packages/client/src/usage/prices.ts` and `fast-multipliers.ts`. Changes: a request above the threshold is priced entirely at long-context rates for every Model (ccusage prices LiteLLM's `_above_200k` fields marginally), and unknown Models, including `codex-auto-review`, are left unpriced.
- **BerriAI/litellm** `model_prices_and_context_window.json` (MIT, outside `enterprise/`) and **anomalyco/models.dev** `api.json` (MIT): the model prices in `packages/client/src/usage/prices.snapshot.json`, fetched on 2026-09-30 and normalized to per-token rates by `packages/client/scripts/update-prices.ts`. The Client fetches both again at run time, and only LiteLLM's vendor-named entries and models.dev's costs are kept.
